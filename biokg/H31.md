# H31: separate hard-negative mining screen

Written 2026-09-05 before the new comparison. H30 full positive masking
failed; its flag remains OFF in every arm of this experiment.

## Hypothesis and three fixed arms

Hypothesis: additional pressure to distinguish the current model's most
confusing training-unknown candidates improves validation ranking, notably
the drug-drug near misses identified in the previous diagnostic.

Seed 0, 12,500 steps, all relations and both training directions:

| Arm | Original sampled CE | Auxiliary sampled CE |
|---|---|---|
| baseline | 100% | none |
| random | 90% at full ramp | 10%, 64 random eligible candidates |
| topk | 90% at full ramp | 10%, 64 highest-scoring eligible candidates |

Each arm uses the original 4096 shared uniform type-matched candidates
per training batch. Auxiliary selection uses this same scored pool, not a
new pool or extra model. Known TRAIN positives (including the current
target) and repeated entity IDs are excluded ONLY from the auxiliary
selection. The original random CE is unfiltered and unchanged. The
random arm controls for auxiliary sample count, training-positive
exclusion and loss mixing; topk versus baseline alone would conflate them.
Random auxiliary selection has an independent, fixed private RNG and does
not perturb the training-triple/candidate sampling stream.

Steps 1–2500 use only original CE. Auxiliary weight ramps linearly from
step 2501 to 3750, reaching 0.1, then remains fixed. Each auxiliary CE
preserves the designated positive. If fewer than 64 distinct eligible
negatives exist, use those available; if none exist, fall back to that
query's original CE. Log the available-slot fraction. Selection uses
detached scores; gradients flow through selected original logits.

Fixed common recipe: k=12, 4x4 blocks, sparse fp32 table, RowAdagrad lr
0.3, Adam lr 0.005, cosine decay, batch 2048, 4096 candidates, trajectory
loss weight 0.1. The trajectory term is not downweighted with the CE
mixture. Same model parameters, initialization and sampled training
batches. No low-rank correction, distillation, full positive masking,
retrieval, probes, or relation-specific loss weights. Record runtime
and training-index memory; equal steps do not imply equal compute.

## Pre-stated decision and protocol

Primary endpoint: full official validation MRR, both directions and the
unchanged fixed candidates/tie convention. Topk must exceed BOTH baseline
and random control by at least 0.003 MRR to warrant a separate longer,
multi-seed confirmation. Report every arm, regardless of outcome. No
count/weight/warmup sweep, seed selection or full-training campaign is
automatically launched. Secondary diagnostics reuse the existing relation
family/direction breakdown; do not change the recipe based on slices.

Only train.pt and valid.pt are loaded. The eligibility index uses only
globalized training triples. Validation queries, labels, error records
and candidates are never mined for training, supplied as model input or
used for gradients. Test is not loaded. Evaluation never invokes the
training eligibility mask. The model is still one model at inference;
the index and selector are training-only, with no extra model parameters.

Known-positive exclusion cannot eliminate unknown true links in an
incomplete graph. Hard mining may amplify those false negatives. This
is a risk being tested, not a claim that every selected candidate is
biologically false. Prior test-informed experimental history remains
part of the disclosure; this new screen does not certify the submission.

The mining flag defaults to none. Full masking, composition,
compositional tables, peers and distillation are incompatible with the
initial mining pilot. Mining checkpoint resume is explicitly unsupported;
the runner always requires a fresh output directory. Existing unmined
workflows retain their behavior.

## Result: hard mining not promoted (2026-09-05)

All three fresh runs finished. The baseline model tensors are bitwise
identical to H29's baseline, allowing reuse of its exact query diagnostic.
Saved arguments differ only in output path and mining mode. All models
have the same 27,124,129 real parameters and finite checkpoint tensors.
Full positive masking is off in all three checkpoints.

| Arm | Validation MRR | Delta vs baseline | Hits@1 | Training time |
|---|---:|---:|---:|---:|
| baseline | 0.7825889281 | — | 0.7044773645 | 165 s |
| random auxiliary control | 0.7860282071 | +0.0034392790 | 0.7088730769 | 227 s |
| top-64 hard auxiliary | 0.7806218209 | -0.0019671072 | 0.7036086588 | 228 s |

Hard selection loses **0.0054063862 MRR against the matched random
control**, failing the pre-stated +0.003 margin against both controls.
No longer training, seed search, relation-specific mining or weight/count
sweep was launched. Mining remains disabled by default; no submission
configuration or published score changed.

The random control gives a preliminary positive signal, but it is not a
hard-mining improvement and is not promoted by this experiment's primary
decision rule. It would need a separately specified full-training and
multiple-seed comparison. Its extra loss also costs more training time;
the present comparison fixes steps, not wall-clock budget. These models
are un-distilled and do not include retrieval.

### Verification, cost and artifacts

All 26 unit/integration tests passed; seven mining tests also ran in the
GPU-enabled environment, including exact CUDA top-k eligibility checks.
Tests cover duplicate IDs, known-positive exclusion, separate RNG state,
explicit loss/gradient equivalence, sparse finite gradients, empty-pool
fallback, the warm-up schedule, train-only index construction and unchanged
validation input. Baseline model tensors match the earlier baseline exactly.

The two auxiliary runs each filled all 1,310,720,000 requested auxiliary
candidate slots: no short/empty-pool fallback occurred in this screen.
Each train-only index uses 731,308,118 bytes (697.4 MiB), with measured
build times 2.1 s (random) and 1.9 s (topk). Training was approximately
38% slower than baseline; hard and random selection had similar runtime.
The index, selector and auxiliary loss are absent from inference.

All three were evaluated with official FP32 candidate ranks. The random
run has one tied query, handled by OGB's averaged-rank convention; the
others have no ties. No validation positive or highest-scoring negative
appears in the corresponding training-query adjacency. No test split
was loaded by training or diagnostics. No validation errors, labels or
candidate sets entered the mining process.
