# H33: full-length confirmation of random auxiliary CE

Written 2026-09-05 before H33 training. User approved random auxiliary
after H32, clarified the 0.8592 leaderboard target, and asked to continue.
This is a bounded single-model experiment, not a submission or a claim
that the leaderboard gap has been closed.

## Six fixed fresh runs

Seeds 0, 1, 2, paired baseline then random auxiliary for each seed.
Each run starts from initialization and trains for exactly 50,000 steps.
No reuse of the short-screen checkpoints, no selection of the best seed,
no early stopping based on validation, and no automatic additional runs.

Common recipe: sparse fp32, k=12, 4x4 blocks, batch 2048, 4096 shared
typed negative candidates, RowAdagrad table lr 0.3, Adam lr 0.005,
cosine schedule over 50,000 steps, trajectory penalty 0.1. Head/tail
sampling stays uniform. No low-rank correction, top-k mining, full
positive masking, retrieval, distillation, ensemble or validation probes.

Baseline uses original sampled CE only. Random auxiliary uses the
unchanged H31/H32 objective: original unfiltered CE mixed with CE over
64 distinct randomly selected eligible candidates from the same scored
pool. Only known TRAIN positives are excluded from the auxiliary pool.
The random selector uses its unchanged private RNG; it does not perturb
the main training-batch/candidate RNG. The trajectory penalty is unchanged.

The warmup remains **2500 steps**, with a **1250-step** linear ramp to
weight **0.1**, then constant. Do not scale these durations to fractions
of the longer run. Extending the total steps necessarily stretches the
common cosine LR schedule relative to H32; it is identical within each
new pair. The model and training implementation are unchanged from H32.
Mining checkpoint resume remains unsupported; output directories must
be fresh. Existing historical checkpoints are not overwritten or deleted.

## Endpoint, reporting and fixed decision

Primary endpoint: official full validation MRR over both directions,
500 fixed typed negatives, original fp32 scores and OGB tie ranks.
Evaluate the final 50,000-step checkpoint, not a selected intermediate.
Report every seed in both arms, arm means and unbiased sample standard
deviations, and all paired gains with their mean and sample std.

The random auxiliary warrants a separately specified next-stage
distilled-model experiment if its mean paired gain is at least **0.002
MRR** AND all three paired gains are positive. This is a compute-allocation
gate, not a significance test or proof of generalization. Mixed or negative
results are retained and reported. No recipe changes based on a partial
pair, family or seed result.

Secondary diagnostics: Hits@1/3/10, both directions, all relation families,
and the existing protein-function/drug-sideeffect bottleneck directions.
Record runtime, parameters, finite tensors, auxiliary-slot availability,
graph/code/checkpoint hashes and exact matched arguments. Identical seeds
within a pair share the initialization and main sampling stream.

The recent 0.78603 score was from a 12,500-step undistilled screen. The
existing full baseline is around 0.816 validation, and the existing
distilled student alone is 0.8321 validation. ComplEx^2's leaderboard
0.8592 is validation (its test score is 0.8583). The published 0.8532
held-out-validation figure for our student plus retrieval is a different
inference pipeline and a validation subset. Do not add the short-screen
gain to it to forecast a new submission score. This experiment tests
whether the training-loss gain survives full training, nothing more.

Sources for this context: repository `README.md` and
[OGB leaderboard](https://ogb.stanford.edu/docs/leader_linkprop/#ogbl-biokg),
checked 2026-09-05. No raw test split is needed to read historical reports.

## Protocol, execution and artifacts

Only TRAIN edges enter updates or the auxiliary eligibility index.
Validation evaluates frozen final checkpoints; it supplies no gradients,
sampling weights, candidates for training, or model inputs during training.
The runner passes `--eval valid`, so only train.pt and valid.pt load.
Test stays unopened. This new comparison does not erase prior experimental
history or certify the existing submission's eligibility.

Run all six jobs sequentially on the local GTX 1080 Ti, approximately
80–90 minutes including independent final diagnostics. Equal steps do
not imply equal GPU time. Available disk space is tight, so check before
each run and diagnosis, refusing to proceed below a safety margin. Do
not delete earlier artifacts to make room. Technical failures stop the
runner and are not treated as model-selection results.

```
DATA=/path/to/data_ogb PYTHON=/path/to/python bash biokg/scripts/run_h33.sh
```

`runs/h33/{baseline,random}_s{0,1,2}/` holds checkpoints and original logs.
`results/h33/prerun.json` freezes source/document hashes and paths;
`seed_{0,1,2}.json` records completed pairs; `confirmation.json` holds
the all-seed aggregate. Independent diagnostic outputs use
`results/error_analysis/h33_{baseline,random}_s{0,1,2}/`.
All output directories and receipts are fresh and existing files are
never intentionally overwritten. The H33 preregistration stays immutable;
write the final interpretation separately in `results/h33/README.md`.
