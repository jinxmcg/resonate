# H35 — two 4×4 operator banks, three combination mechanisms

Preregistered 2026-09-05, before H35 real-data execution. This is an
**operator-only warm-start screen**, not the final jointly trained architecture
or a reproduction of the submission pipeline. Local GTX 1080 Ti only.

## What the second bank stores

One complex 4×4 transformation for each of the existing 36 blocks, for each
of 102 directed relations: 117,504 additional real parameters. It transforms
the same source embedding into a second query vector, compared against the
same candidate entity table. There is no second entity table or external
model at inference.

The hypotheses are alternatives, not claims that we know the biology:

- OR: a second set of plausible answers. A single linear readout can put
  unrelated target groups in competition; two nonlinear-combined readouts
  might represent separate groups. Protein-from-function and side-effect
  recall motivate testing this, but rank deficits do not prove multimodality.
- AND: a second compatibility requirement that can reject close competitors.
  Drug–drug's high Hits@10 but much lower Hits@1 motivates this alternative.
- Mean: ordinary refinement with no candidate-wise nonlinear combination;
  it remains a single candidate-linear query even with two normalized hops.

Do not hard-code a reverse relation, an inverse matrix, or an orthogonal
matrix as the second bank: none is evidence of the missing semantic signal.
Initialize B from the trained A plus a **5% Frobenius-norm perturbation per
4×4 block**, from a private fixed CPU RNG. This breaks identical-branch
symmetry while starting near the already useful distilled representation.
All three two-bank arms get the identical B initialization. Thereafter B's
contents are learned from TRAIN labels through the selected scoring loss.
No hand-assigned biological categories and no validation-error targets.

## Why start by freezing the existing knowledge

Use released BioKG `dist_T2_s0.pt`, SHA256
`b463a8bcc431ada38f4834e235677464f9cd3a86346f88aecd2fd681a01260ef`.
Freeze the distilled entity table, temperature and bank A. Only B learns.
This preserves the learned embedding representation and avoids resetting
embedding optimizer state. The two-bank arms have 27,241,633 total real
parameters but only 117,504 trainable parameters.

A single-bank fine-tune control updates the original bank instead, with the
same frozen table/temperature and the same 117,504 trainable parameters.
Its total parameter count remains 27,124,129. Also retain the fully frozen
student as a zero-update reference. Thus ordinary operator refinement is
not mistaken for an advantage from a second bank.

This is not a conclusion about end-to-end training: freezing A can limit
OR's ability to veto errors and AND's ability to recover low-scoring positives.
Any promising mechanism needs a separate jointly trained confirmation.

## Fixed experiment family

Let `q_j = normalize(H_j normalize(E[h]))` and
`s_j = exp(log_tau) * Re(<q_j, E[t]>)`. Candidate embeddings keep the original
raw norms. Combine after summing over all blocks, not independently per block.

| Arm | Score | Interpretation |
| --- | --- | --- |
| frozen reference | `s_A` | Existing distilled student; no updates |
| single | `s_B`, initialized exactly from A | Matched trainable-parameter refinement control |
| mean | `(s_A+s_B)/2` | Candidate-linear two-bank control |
| or | `T*logaddexp(s_A/T,s_B/T) - T*log(2)` | Smooth union / alternative support |
| and | `-T*logaddexp(-s_A/T,-s_B/T) + T*log(2)` | Smooth intersection / additional constraint |

Fix T=1 in scaled-logit units, no learned gate or temperature sweep. Identical
branches reproduce the reference logits up to fp32 arithmetic for all three
combiners. OR gradients assign more responsibility to the stronger branch
per candidate; AND emphasizes the weaker branch. No hard routing.

All four adaptation runs, in the above order, use:

- Training RNG seed 3500, same relation-proportional TRAIN sampling stream,
  batch 2048, 4096 shared typed negatives, uniform head/tail direction.
- Exactly **5,000 updates**, Adam LR **0.0005**, cosine schedule to zero,
  standard sampled cross entropy, gradient clip 1.0 on trainable parameters.
- No trajectory loss in **any** adaptation arm. Pulling both queries to every
  positive would work against specialization. This CE-only adaptation is an
  explicit change from the original training recipe, shared by the control.
- No distillation loss, auxiliary negative mining, positive masking, new graph
  features, relation-specific mixture fitting, or validation gradients.
- Identical training-stream digest across arms; original frozen tensors
  verified bit-identical after every run. Independently initialize each arm
  from the original checkpoint, never continue one arm from another.
- FP32/complex64, no TF32/AMP, same software/device, one job at a time.
  Log runtime/peak memory: equal updates do not imply equal FLOPs or wall time.

## Evaluation and decisions

- Explicitly load TRAIN and VALID only; no TEST option or legacy score cache.
  Standard [OGB rules](https://ogb.stanford.edu/docs/leader_rules/) apply.
- Fixed 1,000-validation-triple progress probe, private `default_rng(3501)`,
  both directions/all 500 official negatives. Evaluate at initialization and
  each 1,000 updates; report LR, MRR and elapsed time. Probes never change
  gradients, sampling, schedule, stopping or checkpoint selection.
- Full official validation once for the frozen reference and once at the
  fixed endpoint of each adaptation arm: 325,772 directed queries, all 500
  official negatives, average-tie ranks checked against the OGB Evaluator.
- Main comparisons: each arm versus frozen reference, and each two-bank arm
  versus the single fine-tune and mean controls. Report all four results, not
  only a selected winner. Model-only metrics, not feature-pipeline metrics.
- Save per-query rank/RR, branch ranks, positive-score gaps, query-vector cosine,
  B's share of positive/top-candidate support, and family/direction metrics.
  Report recovered baseline top-10 misses and lost baseline top-1 successes.
  These are diagnostics, never training data or learned relation switches.
- Paired-triple bootstrap intervals: 1,000 replicates, seed 3502. Use 98.75%
  intervals for the four comparisons against frozen reference (Bonferroni
  family-wise 95% target); bootstrap is approximate and does not remove
  adaptive development-set reuse or training-seed uncertainty. Other
  pairwise comparisons are descriptive 95% intervals, labeled accordingly.
- Worth confirming only if improvement over frozen is >=0.001 with adjusted
  lower bound >0. A second-bank claim additionally needs >=0.001 over single;
  a nonlinear-combination claim needs >=0.001 over mean. Do not declare
  leaderboard readiness. Confirm any promoted recipe across at least three
  student seeds and against its own features before a final recipe freeze.
- No automatic extension, changed LR, per-relation combination selection or
  favorable early stopping based on progress probes. Record a loss as a loss;
  it rejects this frozen-table/first-bank screen, not the entire architecture.

The [TransG paper](https://arxiv.org/abs/1509.05488) provides precedent for
multiple relation semantics; it does not establish that this architecture
will improve BioKG. Previous test exposure in the project remains disclosed.

## Before real-data launch

Require tests for exact baseline mapping, identical-head reductions, all
combiner gradients, sparse/dense legacy-score parity where applicable,
candidate permutation, frozen parameter invariance, same training stream,
checkpoint round trip, official ties and validation-only loading. Use a
synthetic CUDA smoke to check finite gradients and memory before the campaign.
Do not mutate the original trainer or the submitted model for this pilot.
