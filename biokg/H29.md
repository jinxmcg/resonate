# H29: low-rank relation correction on BioKG

Written 2026-09-05 before running the new variants. WikiKG validation-trained
combiner remediation is deferred; it is not part of this experiment.

Hypothesis: the shared partition into 4x4 relation blocks limits useful
interactions across coordinates. Add U_r V_r* before hop normalization,
keeping a single entity table and one jointly trained model at inference.
U starts random and V zero. Extra initialization preserves the RNG stream,
so common parameters start identically for matched seeds.

Initial screen, seed 0, 12,500 steps in every arm:

| Arm | Correction | Real parameters |
|---|---|---:|
| baseline | none | 27,124,129 |
| global4 | rank 4, connects blocks | 27,359,137 |
| local4 | same factor dimensions, stays within each 4x4 block | 27,359,137 |

The local control has the same parameter count but still represents a
block-diagonal operator. It tests added parameterization/optimization;
extra parameter count alone is not evidence for the cross-block hypothesis.

Recipe: k=12, block size 4, sparse fp32 table, RowAdagrad lr 0.3, Adam lr
0.005 elsewhere, cosine decay, batch 2048, 4096 type-matched sampled
negatives, trajectory loss weight 0.1. No distillation in the initial
screen: first isolate the architecture, then test a surviving variant with
the T=2 student recipe. No simultaneous changes to negative sampling.
Budget is equal steps; record runtime because equal steps are not equal cost.

Compare validation using the official OGB Evaluator, both directions. The
validation-only trainer loads train.pt and valid.pt, never test.pt. All
parameters and any later distillation targets use training data only.
No validation-gradient fitting, test-based selection, or seed selection.

Decision fixed before results: global4 must exceed both baseline and local4
by at least 0.003 validation MRR to justify a 50,000-step comparison and
replication over seeds 0, 1, 2. A positive screen is preliminary; a negative
screen is not a proof about the fully trained architecture. No rank-8 or
temperature sweep is automatically triggered. If global4 does not meet
the stated margin against both controls, report all three and stop this screen.

After confirmation, compare the distilled student alone and with its own
retrieval features on validation. Freeze the complete configuration before
any future final test evaluation. Keep every result and disclose all tuning.
Previous BioKG test-informed promotion decisions remain part of the research
history; this experiment does not erase them or certify the old submission.

Commands (from repository root, installed torch/numpy/scipy/ogb environment):

```sh
python -m unittest discover -s biokg -p test_lowrank.py -v
DATA=/path/to/data_ogb PYTHON=/path/to/python bash biokg/scripts/run_h29.sh
```

The runner executes only the three validation screens. It preserves existing
outputs by refusing to reuse an occupied arm directory. Model checkpoints
can be converted using sparse_to_dense.py and scored by cache_scores.py;
both model scores and analogy features reconstruct the low-rank architecture
from checkpoint arguments.

## Result: not promoted (2026-09-05)

All three runs completed on the GTX 1080 Ti, torch 2.6.0+cu124, numpy 2.5.2,
ogb 1.3.6. Seven numerical/loader/checkpoint tests and the existing sparse
model self-test passed. Receipts and exact console logs are in
[`results/h29/`](results/h29/); the structured receipt records code hashes.
Checkpoints remain in `runs/h29/{baseline,global4,local4}/model.pt` locally.

| Arm | Validation MRR | Delta vs baseline | Training time |
|---|---:|---:|---:|
| baseline | 0.7826 | — | 165 s |
| global4 | 0.7628 | -0.0198 | 224 s |
| local4 | 0.7832 | +0.0006 | 240 s |

The correction that connects blocks loses 0.0204 against the equal-parameter
control and fails the pre-stated +0.003 margin against both controls. No
longer run or distillation campaign was launched. The block-local control
stays close to baseline; the additional parameterization alone does not
produce a useful improvement in this screen. These are early single-seed
results, not a conclusion about every rank or training schedule.

Post-training operator diagnostics (no evaluation labels): global4's
correction/operator Frobenius-norm ratio has median 1.6853 and maximum
3.2874. Of its 102 directed relations, 92 have a nonzero correction; the
median fraction of correction squared norm outside the original blocks is
0.9709 among these 92. The corresponding local4 norm ratio has median
1.2070 and maximum 1.7358, with zero off-block mass. Thus the global
correction did not stay small. This does not establish whether its scale,
mixing, optimization, or another effect caused the validation loss.

The local/global factors use their respective fan-in for initialization;
parameter count and initial predictions match, but optimization dynamics
are not identical. A bounded correction would be a separate hypothesis
with a new validation-only comparison, not grounds to reinterpret or
discard this negative result. No test labels were loaded by these runs.
