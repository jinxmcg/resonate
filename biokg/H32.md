# H32: random auxiliary loss x TRAIN-only head/tail sampling

Written 2026-09-05 before any H32 training. The user requested random
auxiliary training and skewing heads versus tails. This four-arm screen
replaces the not-yet-launched full-length random-only confirmation. The
50,000-step / three-seed confirmation is deferred, not claimed completed.

## Fixed four-arm design

Four fresh seed-0 runs, each 12,500 steps:

| Arm | H31 random auxiliary | Direction sampling |
|---|---|---|
| baseline | off | 50/50 |
| random | on | 50/50 |
| skew | off | fixed train-fanout policy |
| random_skew | on | fixed train-fanout policy |

Keep H31's exact common recipe: sparse fp32, k=12, block size 4,
RowAdagrad table lr 0.3, Adam lr 0.005, cosine schedule, batch 2048,
4096 shared typed negative candidates, trajectory penalty 0.1, no probes.
The random auxiliary has 64 distinct TRAIN-unknown candidates, weight
0.1, 2500-step warmup and 1250-step ramp. Its private RNG is unchanged.
Original CE remains unfiltered. No top-k mining, full positive masking,
low-rank correction, retrieval, distillation or ensemble. Same inference
architecture and parameter count in all arms.

## Direction policy (fixed before results)

For each base relation, deduplicate its TRAIN head-tail pairs. Let E be
the number of unique edges, d_h the number of distinct tails of each
head, and d_t the number of distinct heads of each tail. Define:

```
F_tail = sum_h d_h^2 / E
F_head = sum_t d_t^2 / E
p(tail prediction | relation) = clip(
    sqrt(F_tail) / (sqrt(F_tail) + sqrt(F_head)), 1/3, 2/3)
p(head prediction | relation) = 1 - p(tail prediction | relation)
```

These are mean fanouts encountered by uniformly sampling unique edges,
not means over uniformly sampled distinct queries. Empty relations use
50/50. Duplicate edges cannot affect the policy. The graph digest still
records the original ordered training arrays for provenance.

This modest skew assigns more updates to the direction with higher
training fanout. Fanout is only an ambiguity proxy: more fanout need not
mean more useful gradients or worse filtered MRR. Symmetric relations
stay 50/50. This is not a universal global preference for heads.

Only the existing direction coin's probability changes, from step 1.
The relation-sampling weights and within-relation edge sampling rule
stay fixed. We do NOT importance-correct the loss: the hypothesis is an
intentional change of training exposure/objective. The trajectory loss
therefore sees the same changed direction frequencies as CE. Total
steps and batch size stay equal, but GPU time may differ.

The same seed gives the same initialization. Within each direction
policy, auxiliary selection does not perturb the main training RNG.
Across uniform/skew policies, sources/targets/negative ranges differ;
do not claim identical training batches across these policies. Record
expected probabilities and actual per-relation direction batch counts.
Skew checkpoint resume is unsupported for this fresh-run pilot.

## Endpoints and decision

Primary endpoint: unchanged official validation MRR over both directions
and all fixed 500 typed negatives, with the OGB averaged-rank tie rule.
Report all four arms and these matched effects:

* auxiliary alone: random - baseline;
* skew alone: skew - baseline;
* skew on auxiliary: random_skew - random;
* interaction: (random_skew - random) - (skew - baseline).

The combined recipe warrants a separate full-length multi-seed comparison
if it beats random by at least 0.003 MRR AND skew alone improves baseline.
Skew alone independently warrants such a comparison if it beats baseline
by at least 0.003. These are compute-allocation gates, not significance
tests or evidence of generalization. Report any antagonism with random.
Do not promote a recipe using a winning relation slice. No weight, cap,
direction, seed or warmup sweep, and no automatic longer runs.

Secondary diagnostics: both overall directions and all relation-family
averages, plus the pre-existing protein-function and drug-sideeffect
directional bottlenecks. Compare the fresh baseline/random checkpoints
with H31 at tensor level to check backward compatibility. Record code,
graph and checkpoint hashes, finite tensors, parameter counts, runtime,
and full auxiliary-slot availability. No submission defaults change.

## Protocol and reproduction

Only train.pt and valid.pt are loaded. The direction policy and auxiliary
eligibility index receive only globalized training triples. Neither
receives validation labels, error records or candidates. Policy computation
is a fixed formula without gradients, fitting or RNG. Validation evaluates
frozen models; test is not opened. Direction policy and eligibility index
are never applied at evaluation. This follows the train/validation division
described in [OGB's rules](https://ogb.stanford.edu/docs/leader_rules/), not
a certification of the existing submission or its prior experimental history.

```
python -m unittest discover -s biokg -p 'test_*.py' -v
DATA=/path/to/data_ogb PYTHON=/path/to/python bash biokg/scripts/run_h32.sh
```

The runner requires fresh run, result and diagnostic directories. A
pre-run receipt freezes code/document hashes. After all four runs,
independent validation diagnostics and a summary receipt are generated.
On the local GTX 1080 Ti, budget approximately 15–20 minutes including
loading and diagnostics; this is an estimate, not measured H32 runtime.
