# H37: squared compatibility with exact typed conditional likelihood

2026-09-07. User approved correctness/cost checks, then one matched fresh pair
if practical. Same 4x4 storage, not an ensemble or larger matrix. Inspired by
the squared-circuit method in Loconte et al., "How to Turn Your Knowledge
Graph Embeddings into Generative Models", https://arxiv.org/abs/2305.15944.
This is our adaptation, not a reproduction of that paper's ComplEx2 model.
No external code/weights are needed for this algebraic implementation.

## Fixed model and objective

Keep k12, 144 complex coordinates, 36 free complex 4x4 blocks per directed
relation, 102 directed relations, 27,124,129 real parameters. q is the usual
normalize(H_r normalize(E_source)); no NL1 activation. Let a=exp(log_tau),
u_t=a*Re(q dot conjugate(E_t)), w_t=epsilon+u_t^2. epsilon is fixed at 1e-6,
not learned or tuned. Keep the existing scalar log_tau in both models, with
identical initialization. In the squared model it controls the weight of the
uniform epsilon floor relative to squared compatibility; it largely cancels
when epsilon is negligible. It is not an exponential-softmax temperature.

Squared loss per batch: mean(log Z - log w_positive) + 0.1*trajectory,
where Z sums w_t over ALL entity IDs of the eligible target type. Include
self, designated positive and other fit answers once each in this normalizer;
no training-positive masking or sampling correction. Entity types/counts come
from the permitted transductive metadata, not held-out labels. Cold-in-fit
entity rows can receive gradients through this normalization; disclose this.
The unchanged trajectory term prefers positive alignment even though squared
compatibility can reward either sign. This tests the fixed hybrid recipe,
not every possible squared model or a faithful generative joint distribution.

Use interleaved real views Q and V of q and the eligible complex table so
Re(q dot conjugate(E_t))=Q dot V_t. Compute G=V^T V freshly on EVERY step and
Z=epsilon*N+a^2*row_sum((Q G)*Q). Differentiate through V, G, Q and a without
detachment, stale caching or approximate normalizers. The 288x288 Gram matrix
is a temporary computed statistic, not learned storage or an enlarged 4x4.
At inference score every provided candidate with exactly epsilon+u_t^2;
the common query denominator is unnecessary for ranking. No new model/graph.

Control: original sampled CE + 0.1 trajectory, 4096 typed shared random
negatives. This comparison changes scorer AND likelihood/candidate coverage,
not an isolated activation ablation. Same source/positive batches and directed
relations; negatives are still generated once to preserve the original stream
but unused by the squared loss. No post-hoc squaring of a trained linear model.

Fresh identical seed-0 model state with independent storage, no checkpoint
warm start or teachers. Both train 50,000 updates from scratch; batch 2048,
natural relation frequencies, uniform direction, stream seed 0. Adam H/tau
LR .005, RowAdagrad table LR .3, cosine to zero, global gradient clip 1.
Original linear arm uses sparse table gathers. Squared arm uses dense gathers
because exact normalization gives dense eligible-table gradients. RowAdagrad
implements the same row-wise rule in both cases; synthetic parity is tested.
Same optimizer states initially and same update budget, not equal runtime.
fp32/complex64, no AMP/TF32, 4 CPU threads. No precision or LR sweep.

## Mandatory pretraining pilot

Before real-data updates, test exact Gram probability sums/loss/gradients
against explicit enumeration in float64; gradcheck; zero/near-zero finite
scores; sign symmetry; parameter count and initial state parity; gradients
reach unobserved-but-eligible candidates and are zero outside eligible support
unless a source/positive is there; no detached normalizer; sparse/dense
RowAdagrad parity; checkpoint scorer/config preservation; candidate symmetry,
file guard, private evaluator RNG and average ties. Full-size RTX5090 smoke
uses synthetic data only and the largest BioKG type size 45085.

Fixed practicality gate before measurements: max of two 20-paired-step timing
blocks <= .020 seconds per pair, peak allocated memory <= 8 GiB, all finite
states, direct/Gram probability-gradient agreement within fp32 tolerance.
This bounds the ideal 50k pair to ~17 minutes, not a real-data ETA guarantee.
If this fails, stop after the pilot and report; no cheaper objective or device
change silently substituted. Additional real-training cap 1800 seconds stops
without evaluating partial checkpoints if the practical estimate was wrong.

Pin pilot/source/protocol/data metadata before training; verify source and
artifact hashes afterwards. Only a successful pilot permits the finite
train -> evaluate -> audit job. Audit regenerates initialization, verifies
state/config/optimizer/LR counters and all inputs, then regenerates all
candidate streams/ranks and bootstrap with unchanged models. Not a replay of
every optimizer update. Save both single-model checkpoints, all receipts and
outcomes locally. Existing MN1/NL1 code and artifacts remain immutable.
