# H35B — use the second 4×4 bank to connect previously isolated blocks

Registered before H35B execution, after observing negative single/mean/OR
H35 results and near-parallel queries in its mean arm. This is an explicitly
adaptive follow-up, not part of H35's original four-comparison family. The
H35 campaign is completed unchanged before this starts.

## Distinct hypothesis

H35's extra bank produced another projection inside the same independent
4-coordinate groups. In the mean arm the median query cosine was 0.9987.
This motivates testing another role for B: **cross-block feature mixing**, not
another almost-identical query. The observed similarity does not prove this
is the missing information or that joint two-query training cannot work.

Current `H_A` is block diagonal. It cannot learn a relation-specific coefficient
from a coordinate in one block to an output coordinate in another. Add a second
4×4 bank after A, with a fixed permutation between them:

`q = normalize(P^-1 B_r P A_r normalize(E[h]))`.

B mixes four coordinates taken from four different original blocks. Each new
output can then depend on up to 16 original coordinates through the two layers.
The permutation is fixed, identical for all relations and queries, and contains
no learned or label-derived information. The entity table stays shared.

Test two arms:

- **local:** P=identity. B and A act inside the same original 4-coordinate
  groups. Their product can be folded into one bank; this controls extra
  parameters and the changed optimization parameterization.
- **shuffle:** P is `arange(144).reshape(36,4).T.flatten()`. Each new group of
  four coordinates comes from four different old blocks. Undo P after B.

Both B banks start **exactly identity**, so each initially implements the
existing student's scoring function up to fp32 arithmetic. This avoids making
an arbitrary semantic assignment to the second bank. Learn B solely from TRAIN.
No rotation-invariance claim: B is initialized identity but unconstrained later.

Earlier larger-block and low-rank experiments were not clear wins. This is a
specific warm-start, identity-preserving connectivity test, not evidence that
larger blocks generally improve BioKG.

## Fixed protocol

- Same released student/checksum, frozen E/A/log_tau, 117,504 trainable and
  27,241,633 total real parameters as H35's two-bank arms.
- Same 5,000-update budget, batch 2048, 4096 typed negatives, TRAIN sampling
  seed 3500 and stream digest, Adam 0.0005 cosine→0, clip 1.0, CE only. No
  trajectory/KD/auxiliary loss, positive filtering, feature fusion or new LR.
- Local 1080 Ti, fp32/complex64, no AMP/TF32, sequential runs. H35 reference
  full-validation ranks may be reused; verify checkpoint/dataset hashes.
- Same read-only 1,000-triple validation probe at 0/1000/2000/3000/4000/5000.
  Initial probes must match the frozen-reference probe within 1e-6 MRR; no
  automatic correction or hyperparameter change if a check fails.
- Full official validation only at each fixed endpoint, both directions, all
  provided candidates, official average ties. No TEST option/reads, no
  validation training/graph inputs. Save model, ranks, timings and hashes.
- Primary comparisons: shuffle versus frozen reference and versus local
  control. Report both arms even if worse. Require >=0.001 gain over both,
  and lower bounds >0 for both paired-triple bootstrap 97.5% intervals
  (1,000 replicates, seed 3552; Bonferroni for these two comparisons only).
  These are exploratory adaptive-validation estimates, not a global correction
  across the whole project's search or a multi-seed confirmation.
- If neither passes, keep the original student and report the frozen-embedding
  limitation. Do not automatically start another initializer, permutation,
  combination temperature or joint-training sweep.

Require synthetic tests: identity baseline parity, same-block product
equivalence, actual cross-block dependence only with shuffle, candidate
permutation, frozen tensors, finite B gradients, checkpoint round trip.
