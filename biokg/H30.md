# H30: training-only positive masking

Written 2026-09-05 before the new model comparison.

Hypothesis: sampled single-target CE penalizes alternative known training
answers and repeated copies of the current target. Excluding these
per query will improve validation ranking without modifying the model.
The H29 error analysis motivates the hypothesis but does not prove it.

## Fixed initial comparison

Two fresh runs, seed 0, 12,500 steps, one model each:

| Arm | Sampled-negative CE |
|---|---|
| baseline | unchanged |
| filtered | mask known TRAIN positives for each (source, directed relation) |

Both: k=12, 4x4 blocks, sparse fp32 table, RowAdagrad lr 0.3, Adam lr
0.005, cosine schedule, batch 2048, 4096 uniform type-matched negatives,
trajectory weight 0.1. Same entity/relation parameters and initialization,
same random batches and sampled candidates. No low-rank correction,
distillation, hard-negative mining, retrieval, or evaluation probes.

Masking preserves the designated positive column, drops all sampled copies
of any known training positive only for the relevant query, and does not
resample. Thus the retained negative count varies by query. This screen
tests that precise objective, not a resampling or multi-positive loss.
The trajectory term is unchanged. All-negative-masked CE rows are defined
and finite (zero CE); other loss terms remain unchanged.

The exact index uses compressed, bit-packed per-relation/direction training
adjacency, including an empty sentinel for unseen entities. Index building
does not consume random numbers. It changes training memory/compute, not
parameter count or inference. Record memory, build time, masked-entry
fraction and training runtime. Preserve both checkpoints and all results.

Primary endpoint: full official validation MRR, both directions, fixed
provided negatives and OGB tie convention. An improvement of at least
0.003 MRR warrants a separate full-training/multiple-seed confirmation;
no confirmation or distillation is automatically launched by this runner.
Smaller/negative gains are reported, not reinterpreted via selected slices.
Secondary diagnostics: the same pre-existing relation-family/direction
breakdown, especially drug-drug, protein-function and drug-sideeffect.
No validation-dependent changes to this recipe during the runs.

## Data discipline and boundaries

Only train.pt and valid.pt are loaded. The mask is built solely from
globalized train.pt triples; validation errors/edges/negatives never
enter the training filter, a retrieval graph or a gradient calculation.
Test is not opened. Evaluation does not apply the training mask or alter
OGB's candidate set. Training checkpoints include filter provenance and
counts; resume rejects a different filtering mode or training graph.

The new flag defaults off. Composition, compositional tables, peers and
distillation are explicitly unsupported with the flag in this initial
implementation; masked KL needs separate care to avoid 0-times-infinity.
Existing unfiltered workflows are unchanged. A successful pilot would
still need confirmation in the distilled single-model pipeline before
claiming any submission improvement. Prior test-informed research history
is not erased or certified by this new experiment.

```sh
python -m unittest discover -s biokg -p 'test_*.py' -v
DATA=/path/to/data_ogb PYTHON=/path/to/python bash biokg/scripts/run_h30.sh
```

The runner refuses an existing output directory and executes only the
two validation-only initial runs. No submission or external write occurs.

## Result: not promoted (2026-09-05)

Both fresh runs completed on the GTX 1080 Ti. The unfiltered checkpoint
is bit-for-bit identical in every model tensor to H29's baseline, so its
existing exact per-query validation diagnostic can be reused. The saved
arguments differ between H30 arms only in output path and the filtering
flag. No other model or loss hyperparameter changed.

| Arm | Validation MRR | Hits@1 | Hits@10 | Training time |
|---|---:|---:|---:|---:|
| baseline | 0.7825889281 | 0.7044773645 | 0.9253005169 | 168 s |
| filtered | 0.6712563624 | 0.5696223125 | 0.8653014992 | 219 s |

Delta: **-0.1113325657 MRR**, well below the pre-stated +0.003 margin.
Non-top-1 queries rise from 96,273 to 140,205; queries outside the top
10 rise from 24,335 to 43,881. No full-training confirmation, additional
seed search, partial-mask sweep or distillation was launched. The flag
stays off by default and the current submission is unchanged.

Every pre-existing relation family regresses (both directions combined):

| Family | Baseline MRR | Filtered MRR |
|---|---:|---:|
| Drug-drug (38 relations) | 0.6444 | 0.5792 |
| Protein-function | 0.7545 | 0.6337 |
| Drug-sideeffect | 0.2399 | 0.1741 |
| Function-function | 0.9373 | 0.7429 |
| Disease-protein | 0.5455 | 0.3737 |
| Drug-protein | 0.7872 | 0.6521 |
| Protein-protein (8 relations) | 0.9530 | 0.9183 |
| Drug-disease | 0.2614 | 0.1930 |

The filter masked 3,547,038,871 of 104,857,600,000 sampled candidate
entries (3.38271987%, including repeated candidates). The training index
uses 731,308,118 bytes (697.4 MiB) and took 2.0 s to build; it is not
part of the model checkpoint's parameter tensors or inference scorer.
Training was about 30% slower, excluding build/data/evaluation time.

Verification: all 19 unit/integration tests passed; the eight masking
tests also ran in the GPU-enabled environment, including exact CUDA mask
membership checks. A further independent sorted-edge lookup on the actual
training graph matched 1,253,376 mask entries across all 102 directed
relations, with every designated positive masked when sampled as a
negative. Both checkpoints are finite and have identical model keys and
parameter counts. The integration test checks that only training triples
build the filter and that the original validation split reaches evaluation
unchanged. No validation/test edge entered the filter; no test split was
loaded by the training or diagnostic runs.

Post-training observations, not causal conclusions: the learned positive
score multiplier exp(log_tau) rises from 7.72 to 32.28; median raw entity
norm rises from 2.99 to 3.77. Removing training-positive competition may
have removed useful regularization or changed the optimization balance.
Neither the lower masked loss nor these parameter statistics establish
overfitting or the cause of the rank regression. Scaling all inference
scores by a positive constant would not fix ranks; temperature matters
here as a possible training-dynamics hypothesis, not a post-hoc rank fix.
This is a negative result for full masking under the fixed recipe, not
proof that all filtered or multi-positive objectives fail.
